## Defects

### 1 · `registrableDomain` uses 21 hardcoded suffixes, not the PSL

**Severity: medium — security.** `ProtectionSettings.swift:32`

`HostKey.isSameSite` now gates two security decisions: whether a cross-site
popup is held rather than followed (`WebView.swift:370`), and whether a
cross-site redirect is cancelled during theater (`WebView.swift:406`).

`multiPartSuffixes` omits `.com.pl`, `.co.il`, `.com.ua`, `.com.pk`, `.co.th`,
`.com.vn`, `.com.ar`, `.com.ng` and most other ccTLD second levels. For any of
them:

```
registrableDomain("evil.com.pl")   -> "com.pl"
registrableDomain("victim.com.pl") -> "com.pl"
isSameSite(...)                    -> true
```

The redirect is allowed through — the exact attack the guard exists to stop.

The in-file `ponytail` note calls this a cosmetic ceiling where two unrelated
sites "count as same-site." That was true when the function only resolved user
exceptions. It stopped being cosmetic when `isSameSite` became a security
predicate, and the note was not revisited.

**Fix:** bundle the real Public Suffix List and match against it. The comment
already names this as the upgrade path and says nothing else needs to change.
`ProtectionSettingsTests` covers the behaviour, so the swap is guarded.

---

### 2 · Switching protection level purges the other level's compiled lists

**Severity: low.** `RuleListController.swift:149`, `:187`

`purgeStaleCompilations(keeping: wanted)` is passed only the **current level's**
lists. Standard excludes `annoyances`, so:

```
Standard -> Strict -> Standard
```

deletes and recompiles 49,553 rules on every round trip — a 638 KB inflate plus
~1.6s compile that the content-hash cache was built to avoid.

**Fix:** pass `catalog.lists` instead of `wanted`. The purge is meant to drop
compiles orphaned by *regenerated rules*, not by a level the user is not
currently on.

---

### 3 · Native popup blocks are overwritten by the page-world counter

**Severity: low.** `WebView.swift:560`

Two counters measure different things:

- `popupsBlocked += 1` at `:374` (cross-site window held) and `:409` (theater
  redirect cancelled) — native side.
- `window.__cpPopupsBlocked` — `popupguard.js`, page world.

`didFinish` **assigns** rather than adds:

```swift
self?.page.popupsBlocked = value as? Int ?? 0
```

Any native block landing between `didStartProvisionalNavigation` and `didFinish`
is erased. Visible symptom: a blocked-popup count that goes down.

**Fix:** keep the native tally in its own property and publish the sum.

---

### 4 · Non-`linkActivated` popups are dropped silently

**Severity: low.** `WebView.swift:365`

`createWebViewWith` returns `nil` for anything that is not `.linkActivated` —
including `.formSubmitted` with `target="_blank"`. No counter, no
`blockedExternal`, no user-visible offer. A legitimate form that opens in a new
window is a dead button with no explanation.

**Fix:** treat a cross-site form submission the same as a cross-site link —
hold it and offer it.

## What to do, in order

Nothing here is a new feature. The engine is done; what remains is identity,
hardware, and one measurement.

### Blockers — cannot ship without

1. **App icon.** No asset catalogue exists. Upload is impossible until one does.
2. **`MARKETING_VERSION` 0.1 → 1.0.**
3. **Push to a remote.** Four CI jobs are written, correct, and have never
   executed once. Nothing above stays verified without this.
4. **Privacy policy at a public URL**, contact address filled in.
5. **One device build**, signing team added.

### The measurement that decides everything

6. **Ten real video sites, written down, with a denominator.** Which worked,
   which broke, which mode fired, what escaped. No success rate exists today, so
   every quality claim is currently a guess. Each failure becomes a fixture.
7. **TestFlight, 25–50 testers.** Hold for >99.5% crash-free, >80% Watch clean
   success, <5% protection-disable rate.

### Defects above

8. Public Suffix List — do this one first, it is the only security finding.
9. Purge scope.
10. Popup counter.
11. Cross-site form submissions.

### What separates a good app from a finished one

12. **Runtime filter updates** — `ROADMAP.md` items 19–20. Rules change only
    when the app updates. The 30-day staleness warning is honest mitigation, not
    a fix. A blocker that cannot refresh is a depreciating asset, and this is
    the last structural gap in the product.
13. **Localisation** — `SWIFT_EMIT_LOC_STRINGS` is on with no string catalogue,
    so every label is English-only.
14. **On hardware:** performance under 184k rules, landscape theater, iPad Split
    View and Stage Manager.

## Assessment

**7.5/10 today.** Strong engineering, complete feature surface, zero real-world
evidence.

The code earns that on specifics, not impressions: `Task.isCancelled` checked
*after* each await with the bug that taught it recorded in a comment;
`purgeStaleCompilations` existing at all because content-hash keys orphan old
compiles; `testWhetherIgnorePreviousRulesReachesAcrossLists` proving a written
plan wrong and the plan changing; the cheap list attached first so the first
navigation is filtered in 20ms rather than naked for ten seconds.

What holds it at 7.5 is not code quality. It is that 210 passing tests all run
against fixtures this project wrote. A page you author is a cooperative
opponent. The sites this app exists for are not, and none of them have been
tried.

**The app icon and the ten-site measurement move this further than any code
written this week.**
